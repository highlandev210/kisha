# Kisha MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Kisha's first installable build: every MVP-tagged requirement (setup, Home with a live daily allowance, quick entry, history by day, fixed costs, automatic period rollover, ₹ formatting).

**Architecture:** A pure-Kotlin `:core:allowance` module holds all budget math (cycle dates, the allowance formula, money parsing) and is covered by JVM unit tests. `:app` holds Room storage, two repositories, ViewModels and Material 3 Expressive Compose screens, wired by a manual `AppContainer`. The allowance is never stored: ViewModels combine Room flows with a "today" flow and call the engine on every emission.

**Tech Stack:** Kotlin 2.2.10 (AGP 9.5.1 built-in Kotlin), Compose BOM 2026.09.00 with material3 overridden to 1.5.0-rc01, Room 2.8.5 + KSP 2.3.13, lifecycle 2.11.0, kotlinx-coroutines-test 1.11.0, Turbine 1.2.1, JUnit 4.

**Spec:** `docs/superpowers/specs/2026-11-07-kisha-requirements.md`

## Global Constraints

- 100% native: Kotlin + Jetpack Compose. No Flutter, React Native, Compose Multiplatform UI, WebView or PWA.
- minSdk 29, targetSdk 37, compileSdk 37 (as generated). Device under test: Redmi Note 6 Pro, Android 13 (API 33).
- No `INTERNET` permission. No analytics, ads, crash reporting, Google Play Services or proprietary dependencies (F-Droid buildable). Licence Apache-2.0.
- Money is `Long` paise everywhere. Never `Float`/`Double` for money.
- Today's allowance is derived at read time from the tables, never stored.
- UI root is `MaterialExpressiveTheme(motionScheme = MotionScheme.expressive())`. Components come only from `androidx.compose.material3`. No XML views, no third-party UI kits.
- Outside `ui/theme/`, no `Color(0x…)`, literal `.sp` font sizes or literal corner radii: use `MaterialTheme.colorScheme/typography/shapes`.
- Experimental opt-ins (`ExperimentalMaterial3Api`, `ExperimentalMaterial3ExpressiveApi`, `kotlinx.coroutines.ExperimentalCoroutinesApi`) live only in `app/build.gradle.kts` `compilerOptions.optIn`. No `@OptIn` annotations in source.
- Every user-visible string is in `app/src/main/res/values/strings.xml`. All copy is original; nothing from Chelav.
- Navigation items, button groups and the add button always show text labels (DP-5). Every icon-only control has a `contentDescription`.
- Touch targets ≥ 48 dp. Keypad keys and primary buttons ≥ 56 dp tall. Status (on track / low / over) always shows an icon and text, never colour alone.
- Primary `Button`s pass `shapes = ButtonDefaults.shapes()` so they shape-morph when pressed (UI-7). Choice controls are connected `ToggleButton` groups (UI-5).
- Manual DI through `AppContainer`. No Hilt or Dagger. No navigation library.
- Every "today" calculation reads the zone at call time through `TimeSource.zone()`. Never cache a `ZoneId` or `Clock.systemDefaultZone()`.
- Package root `com.example.kisha`; core module package `com.example.kisha.allowance`.
- Commands assume `cd ~/AndroidStudioProjects/kisha` and `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`. Instrumented tests (`connectedDebugAndroidTest`) need the phone attached (`adb devices` shows `device`). To run one instrumented class, use `./gradlew :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=<fqcn>`.

## Decisions this plan makes

The spec is silent on these, or contradicts itself. Each one is locked here so no task re-decides it.

1. **HM-5 vs UI-4.** A FAB menu needs two taps to reach expense entry, but HM-5 requires one. Resolution: one large FAB labelled "Add" opens the expense sheet directly. The sheet starts with a connected **Expense | Income** toggle, so income is one more tap. `FloatingActionButtonMenu` is not used in MVP.
2. **Rounding.** `base = Math.floorDiv(flexible − spentBefore, daysLeft)` in paise, so the app never over-promises. The Home number shows whole rupees, floored (81 034 paise → "₹810"; −81 034 → "-₹811"). Lists show paise only when non-zero.
3. **Status.** OVER if `remaining < 0`. Otherwise LOW if `base ≤ 0` or `remaining * 5 < base`. Otherwise ON_TRACK.
4. **Cycle start encoding.** `cycleStartDay`: 1–31 = day of month, clamped to the month's length. −1 = last working day (last Mon–Fri; holidays ignored). MONTH is stored as 1.
5. **Fixed-cost and base-income edits** apply to the open (latest) period immediately and to future periods. Closed periods keep their snapshot.
6. **Rollover** creates every missing period contiguously (each starts the day after the previous one ends) and sets `closedAt` on all but the newest. `leftoverAction` stays null (BP-2 is v1).
7. **Engine dating.** An entry's day is its local date in the current zone, clamped into the period's range. For day d: `S<d` = entries before d, `S_d` = entries on d, and entries after d are ignored. Extra income counts when its clamped date ≤ d.
8. **Schema.** All spec columns are created now with defaults, including those for v1 features (savingsTarget, allowanceMode, affectsAllowance, recurring, paidInPeriodId, colour, hidden, leftoverAction), so v1 needs no migration for them. One added column: `BudgetConfig.indianGrouping` (ST-1). `Expense.categoryId` is nullable (null shows as "No category").
9. **Default category names** are written from string resources when setup completes.
10. **Backup.** `android:allowBackup="false"`, and both backup-rules XML files are deleted, so Google cloud backup never copies data off the device.
11. **Expense date picker** allows dates from the first period's start to today.
12. **Onboarding vs main** is decided by whether the `BudgetConfig` row exists. The three tabs (Today, History, Settings) are `rememberSaveable` state.

**Open (not blocking MVP):** the final `applicationId` and package name must be chosen before the first public release. `com.example.*` is rejected by the Play Store.

## Review Focus

1. **Concurrent rollover at midnight.** Home and History both call `ensureCurrentPeriod`, which must create exactly one new period. Test: Task 5, `concurrentEnsureCreatesOnePeriod`.
2. **App unopened for months, or clock jumps forward.** Every missing period must be created, with no gaps, and today's period must be current. Test: Task 5, `rolloverFillsGapsAcrossMonths`.
3. **Clock set back before the current period, or travel west across midnight.** No new period, no crash: show the earliest period with the day clamped to its start. Tests: Task 3, `dayOutsideRangeClampsToEdge`; Task 5, `ensureCurrentPeriodDoesNothingWhenTodayBeforeLatest`.
4. **Garbage amounts.** "", ".", "1.234", "-5", "abc", pasted commas, and values over the maximum must be rejected or normalised, and zero cannot be saved. Tests: Task 3, `MoneyTest`; Task 10, `AmountInputTest`.
5. **Money exhausted, or income below fixed costs.** Today and period-left must show negative values with OVER, never clamped to zero, including in the onboarding preview. Tests: Task 3, `exhaustedPeriodShowsNegative` and `incomeBelowFixedShowsNegative`; Task 8, `fixedAboveIncomePreviewShowsNegative`.
